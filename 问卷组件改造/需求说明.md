# 问卷组件改造需求说明

> 需求来源：禅道需求 需求 A【项目 A】PC端与移动端问卷配置组件功能优化需求
> 涉及组件：`PC问卷组件`（PC 问卷内容配置）、`移动问卷组件`（移动问卷渲染）
> 提交对象：低代码平台组件团队

---

## 一、需求背景

项目 A（问卷/测评项目）使用平台内置问卷组件搭建问卷业务。当前三个交互痛点：

1. PC 配置页题目过多时，左右两侧功能区不随页面滚动，配置人员需反复滚动来回操作。
2. 多选题缺少「最多选择 x 项」的限制配置能力。
3. 移动端填写时，对「最多选 x 项」无任何提示或拦截。

---

## 二、三个优化点详述

### 优化点 1：PC 配置页左右功能区悬浮

**现状**：`PC问卷组件` 的左侧「题型栏」和右侧「题目配置区」为固定定位，页面滚动后脱离可视区。

**期望**：题目数量超过一屏高度时，左右两个功能区能够**悬浮（sticky）**在可视窗口顶部，或悬浮于组件可视区中间，随滚动保持可见。

**改造点**：`PC问卷组件` 组件内部布局容器增加 `position: sticky`（或等价实现），并保证在题目较少（不超一屏）时保持原有静态布局。

**验收标准**：配置 15 道以上题目，滚动页面时左侧题型栏与右侧配置区始终可见；题目少于 5 道时不出现异常悬浮。

---

### 优化点 2：多选题「最多选 x 项」配置

**现状**：`PC问卷组件` 多选题只支持选项增删、`multipleType`、`multiplePartsScore`，无法限制用户最多选择几个选项。

**期望**：多选题配置区新增「最多可选数量」输入项（如：10 个选项里最多选 3 个），配置后随问卷 DSL 一起保存。

**改造点**：
- `PC问卷组件` 多选题配置面板新增「最多可选」数字输入框（0 或空 = 不限）。
- 该值写入问卷 DSL（字段设计见第三节）。

**验收标准**：配置多选题并设置「最多选 3 项」后，保存再打开，该值能正确回显。

---

### 优化点 3：移动端选满提示

**现状**：`移动问卷组件` 渲染多选题时不识别「最多选 x 项」，无任何限制或提示。

**期望**：读取 DSL 中的 `maxSelect` 字段，选满后按以下任一方案提示：

- **方案一（硬限制）**：题目底部常驻提示「最多选 N 项，已选 X 项」；选满 N 项后，其余未选选项置灰不可点。
- **方案二（软校验）**：题目底部提示「最多选 N 项」；选满后仍允许点选，但底部出现红字校验提示「最多只能选 N 项」，且提交时拦截。

**改造点**：`移动问卷组件` 多选题渲染逻辑读取 `maxSelect`，实现提示 + 拦截（推荐方案二，体验更友好）。

**验收标准**：移动端填写「最多选 3 项」的多选题时，选满后出现明确提示；提交时校验拦截生效。

---

## 三、DSL 字段设计（`maxSelect`）

### 3.1 字段定义

| 字段 | 类型 | 取值 | 含义 | 默认 |
|------|------|------|------|------|
| `maxSelect` | number(int) | `0` 或空 | 不限选 | `0` |
| `maxSelect` | number(int) | `N > 0` | 最多选 N 项 | — |

### 3.2 字段位置（两种方案，推荐方案 A）

**方案 A（推荐）：题目顶层，与 `type` 平级**

优点：渲染组件直接读 `q.maxSelect`，逻辑最简；向后兼容（老问卷无此字段，缺省视为不限）。

```json
{
  "webId": "q_a1b2c3",
  "question": "请选择你关注的健康话题（最多选 3 项）",
  "type": 2,
  "subType": 21,
  "maxSelect": 3,
  "setting": {
    "options": {
      "multipleType": "",
      "multiplePartsScore": "",
      "options": [
        { "webOptionId": "opt_1", "option": "高血压", "optionIndex": 1, "fillBlank": false },
        { "webOptionId": "opt_2", "option": "糖尿病", "optionIndex": 2, "fillBlank": false },
        { "webOptionId": "opt_3", "option": "冠心病", "optionIndex": 3, "fillBlank": false },
        { "webOptionId": "opt_4", "option": "其他", "optionIndex": 4, "fillBlank": false }
      ]
    }
  }
}
```

**方案 B（备选）：放在 `setting.options` 内，与 `multipleType` 平级**

```json
{
  "type": 2,
  "subType": 21,
  "setting": {
    "options": {
      "multipleType": "",
      "multiplePartsScore": "",
      "maxSelect": 3,
      "options": [ ... ]
    }
  }
}
```

> 方案 B 的优点是「多选相关配置都集中在 options 里」，但渲染端读取路径更深（`q.setting.options.maxSelect`）。建议最终以组件团队现有 `multipleType` 字段的读取惯例为准。

### 3.3 向后兼容性

- 老问卷 DSL 无 `maxSelect` 字段 → 组件按 `maxSelect = 0`（不限）处理，行为与现状完全一致。
- 新问卷 `maxSelect = 0` 或未填 → 不限选，不显示提示。
- 仅 `type = 2`（多选）时 `maxSelect` 生效，其他题型忽略该字段。

## 四、组件改造点清单

| # | 组件 | 改动 | 涉及文件/模块 |
|---|------|------|--------------|
| 1 | PC问卷组件 | 左右功能区加 sticky 悬浮 | 组件布局容器 |
| 2 | PC问卷组件 | 多选题面板加「最多可选」输入框 | 多选配置面板 |
| 3 | PC问卷组件 | 保存时把 maxSelect 写入 DSL | 组件取值/序列化 |
| 4 | 移动问卷组件 | 多选渲染读 maxSelect | 多选渲染分支 |
| 5 | 移动问卷组件 | 选满提示 + 拦截 | 多选选择逻辑 |
| 6 | （后端兜底）submitSurvey | 服务端校验 maxSelect | 提交校验逻辑 |

> 第 6 项为**可选**增强：前端拦截可被绕过，建议后端提交时也校验「多选答案数量 ≤ maxSelect」，防止脏数据。

## 五、验收测试用例

| 用例 | 步骤 | 预期 |
|------|------|------|
| TC1 | PC 配置 20 道题，滚动页面 | 左右功能区始终可见（sticky） |
| TC2 | PC 配置多选题，设「最多选 3」，保存再打开 | maxSelect=3 正确回显 |
| TC3 | 移动端填写该多选题 | 底部提示「最多选 3 项」 |
| TC4 | 移动端选满 3 项后再点第 4 项 | 出现校验提示 / 拦截，无法提交 |
| TC5 | 老问卷（无 maxSelect）移动端填写 | 行为与现状一致，无提示无限制 |
| TC6 | 单选/下拉题不受 maxSelect 影响 | 正常单选/下拉 |

---

## 六、与后端/数据层的接口约定

- DSL 存储在 `问卷配置表.dsl`（JSON 字符串）。
- `maxSelect` 是题目（questionList 项）层级的字段，随 DSL 整体读写，**不需要**单独加数据库列。
- 答案表 `答案表` 中多选题答案 `desc` 存选中项（如逗号分隔的 `webOptionId` 或多个值），后端校验时据此判断数量是否超过 `maxSelect`。
