# 黑名单列表排序 · V4.0




## 一、业务背景：

> 租户：项目 A 机构 A
> 需求：查询黑名单列表根据创建时间倒序排序，现在是乱序的
> 禅道工单：工单 A
> API：BI 已隐去（黑名单列表查询）
> 逻辑：列表查询逻辑 A（已隐去）



## 二、问题根因

`列表查询逻辑 A` 逻辑调用的是中央服务 `列表服务 A` 的黑名单列表接口：

```
URL:    接口 A
Method: POST
Service: 列表服务 A（服务注册中心）
```

该接口的 body 入参只有 `type`、`value`、`state`、`isPermanentBan`、`page`、`pageSize`，**没有排序参数**。

经验证：跨 多个租户搜索所有调 `列表服务 A` 的 多个 BI，**没有任何一个使用 sortField/sortOrder 参数**。中央服务不支持服务端排序。

**当前逻辑流程**：

```
BEGIN
  → BI调用（列表服务 A 中央服务，无排序）
  → 变量赋值（直接透传 BI 返回数据）
  → END
```

返回的 records 按数据库默认顺序（插入顺序）排列，所以是"乱序"。



## 三、方案思路

将中央服务黑名单列表接口的**默认排序改为 `createTime` 降序**（即不传 sort 参数时也按创建时间倒序返回），这样即使 BI 不传排序参数，列表也是有序的。

**需求：黑名单列表接口默认按创建时间降序排列**

**接口**：`POST 接口 A`

**当前行为**：返回数据按数据库默认顺序（插入顺序），无序。

**期望行为**：

1. **默认排序**：不传 sort 参数时，按 `CREATE_TIME DESC`（创建时间降序，最新在前）返回。
2. **支持自定义排序**（可选）：接受 `sortField` 和 `sortOrder` 参数，允许调用方指定排序字段和方向。

**建议参数设计**：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `sortField` | String | 否 | `createTime` | 排序字段名（如 createTime、value 等） |
| `sortOrder` | String | 否 | `desc` | 排序方向：`asc` 升序 / `desc` 降序 |



## 四、**影响范围**：

所有调用此接口的项目（当前有 多个租户使用），改为默认排序后全部受益，无需各项目单独配置。
